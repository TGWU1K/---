# 集港抢单助手（jigang-daka-helper）

针对「北斗集港服务」微信小程序的**自动点打卡**工具：司机把手机放在车上跑，脚本负责反复点「集港打卡」并自动过数字验证码，**抢到单就停手响铃提醒，绝不代替司机点「确认」**。

> 本项目只做「让司机的手指歇一会儿」，不做无人值守抢单，也不绕过平台的任何风控。

## 这是什么

业务流程是这样的：货车进场前，司机在微信里打开「北斗集港服务」，反复点「集港打卡」→ 每次弹一道数字验证码 → 每过一道有概率摇中一单运输任务 → 中单后弹出「空车进场位置 J26xxx」+ 红色「确认」按钮。

司机的痛点不是点「确认」（那个没有时限），而是**要一直戳屏幕点打卡**。所以这个工具只把「点打卡 + 过验证码 + 判断有没有中」自动化，中单后立刻停手、响铃、震动、存图，等司机自己来处理。

## 怎么做到的

- **不开 root、不用 OCR**：验证码是纯像素识别。上方 3 个数字必然出现在下方 6 个候选里，所以拿每个上方字的字形去 6 个候选里「找自己」——中心 44×44 窗口取墨迹、紧包围盒归一化成 24×24 二值向量，逐位不匹配率作为距离，贪心互斥分配 + 阈值/边际双校验。
- **点击**走无障碍服务 `dispatchGesture`；**取图**优先无障碍 `takeScreenshot`（Android 11+），退化到 MediaProjection 投屏。
- **状态判定**全用颜色 + 采样点：弹窗在不在、打卡按钮在哪一行、点对后圆圈变绿、结果卡「‹」的重心位置。

## 构建

不需要 Android Studio，也不需要 Gradle。只需要 JDK 17 + Android build-tools（`aapt2` / `d8` / `zipalign` / `apksigner`）+ 一个 `android.jar`：

```bash
# 打卡助手 APK
bash 打卡助手APK/build_daka.sh
# 体检 APK
bash 体检APK/build_probe.sh
# 假打卡页（联调用）
bash 假打卡页/build_mock.sh
```

产物在各自的 `_build/out/` 下。签名用的是仓库外的 debug keystore（脚本里指向本地路径），自己跑请改成你自己的 keystore。

## 联调环境（官方 AVD）

MuMu 被卸载后改成官方 Android Emulator，装好即用：

```bash
export ANDROID_SDK_ROOT=C:/tmp/ljq/sdk     # 必须正斜杠
$ANDROID_SDK_ROOT/emulator/emulator.exe -avd daka33 \
  -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader_indirect
```

- AVD `daka33`：Android 13 / `hw.lcd 720x1600` / density 180 / 内存 2048 / `swiftshader_indirect`
- 硬件加速靠 AEHD（`extras;google;Android_Emulator_Hypervisor_Driver`，需管理员权限装一次，`sc query aehd` 应为 RUNNING）
- 两个坑：① adb 命令里出现 `/sdcard/...` 必须加 `MSYS2_ARG_CONV_EXCL='*'`，否则 Git Bash 会把它转成 Windows 路径；② **HARDWARE 位图必须先 `copy(ARGB_8888,false)` 再读像素**，`Canvas.drawBitmap` 画硬件位图会直接抛异常（这正是之前「无障碍截图拿不到帧、err=-9」的真凶）

## 安全红线（代码里是硬约束，不是建议）

1. **永不点击「确认」**——每次点击前先跑一次成功判定，坐标表里根本没有「确认」区域
2. 只在微信前台动作，切走 / 熄屏立刻停
3. 连续 5 轮异常、连续 20 轮没中、40 轮上限，任一触发即停
4. 不 root、不装 Xposed、不改定位、不用微信分身
